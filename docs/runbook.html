Sign-ins

All three CLIs sign in as admin@<tenant>.onmicrosoft.com (since 2026-11-01; ADR-0015). az and pa are machine-global. The the-agents repo uses the same tenant, so they rarely need switching now, but check them before you run anything here (KI-08).

az login --tenant <tenant-id>
az account set --subscription <subscription-id>
pac auth create --environment https://og-svc.crm.dynamics.com
cd code-app && npx --no-install pa auth login

Check:

az account show --query "{user:user.name, tenant:tenantId}"   # admin@<tenant>, <tenant-id>
pac org who                                                   # og-svc
cd code-app && npx --no-install pa auth status                # active account admin@<tenant>

If pa is signed in to both tenants, switch the active account instead of signing in again: npx --no-install pa auth switch --account admin@<tenant>.onmicrosoft.com --non-interactive. The previous tenant's account was admin@<previous-tenant>.onmicrosoft.com.

Re-seed the data

The seed data is relative to an anchor date (default today), so dates go stale. Re-seed on recording day, or a day or two ahead with --anchor set to the recording date. The Command Center and the agent measure against the real clock, so data seeded ahead looks off until that day, then reads correctly.

python scripts/seed_data.py --reset                        # anchor = today
python scripts/seed_data.py --reset --anchor 2026-10-27    # anchor = a given date
python scripts/expected_kpis.py --as-of 2026-10-27         # the numbers as they'll read that day
  • Takes about 10 minutes: deletes run one at a time (KI-24).
  • Claude Code's auto mode blocks it as a mass delete unless O'G says "re-seed it" in that turn (KI-25).
  • Creates 36 patients, 36 plans (22 active, 14 discharged in the prior 14 days) and 209 tasks. The hero is DP-1001 Miguel Reyes (Dataverse).
  • Clears the saved agent drafts (amc_patientsummary, amc_priorauthpacket) and reopens every barrier a rehearsal closed.

Checks

python scripts/preflight.py          # publisher, solution and tables exist; no collisions
python scripts/verify_seed.py        # data counts and the hero patient
python scripts/expected_kpis.py      # the Command Center's numbers, computed from live data
python scripts/test_foundry.py       # both deployments, direct with Entra ID
python scripts/test_foundry.py --apim   # both deployments through APIM (the connector's path)
python scripts/check_governance.py   # read-only: Managed Environment, and which DLP policies apply

Edit the agent

pac copilot pull --project-dir ./agent
# edit agent/settings.mcs.yml, agent/capabilities/tools/*.mcs.yml or agent/behaviors/*

  • Check the preferred solution before the push, and solution membership after it (below).
  • The MCP tool trim is the allowedTools list in agent/capabilities/tools/amc_dataverse-mcp.mcs.yml.
  • Inline skills get rewritten to behaviors/<name>/SKILL.md + skill.mcs.yml on the first push (KI-16).
  • Don't put multi-line text in pac copilot init --instructions (KI-04). Never init again without reporting and removing the solution and publisher it creates (KI-03).
  • Log the change in the Copilot Studio edit log, then publish.

Solution membership

New components land in the maker's preferred solution, along with the tables they depend on (KI-05). O'G's preferred solution is now AMCDischargeNavigator (it was MedicaidIntegrityLab until 2026-10-19). Never let AMC components land in another project's solution.

  1. Before an init or push: check the preferred solution. 
    GET /api/data/v9.2/WhoAmI                                        → UserId
GET /api/data/v9.2/usersettingscollection(<UserId>)?$select=_preferredsolution_value
GET /api/data/v9.2/solutions(<that id>)?$select=uniquename     → AMCDischargeNavigator
  2. After it: for each of our object ids (the bot 995d5b75-…, its components, the connection references, the 3 tables, the connector, the Code App a1951694-…), list the solutions that contain it. 
    GET /api/data/v9.2/solutioncomponents?$select=objectid,componenttype
    &$filter=objectid eq <id>&$expand=solutionid($select=uniquename)
    Anything other than AMCDischargeNavigator (and the system Default solution) needs removing.
  3. Remove membership only. This deletes nothing, but it changes another project's solution, so get O'G's OK first. 
    POST /api/data/v9.2/RemoveSolutionComponent
{
  "SolutionComponent": {
    "@odata.type": "Microsoft.Dynamics.CRM.solutioncomponent",
    "solutioncomponentid": "<objectid>"
  },
  "ComponentType": <componenttype>,
  "SolutionUniqueName": "<other solution>"
}
    Passing a raw ComponentId instead of the entity reference returns 400.

Render the hero video

The hero video is a web page, docs/hero/animation.html, rendered frame by frame to docs/assets/hero.mp4. Every animation starts at 0 with its own delay, so ?capture pauses them all and window.seek(ms) shows any moment.

  1. Serve the docs: cd docs && python -m http.server 8765. Open http://localhost:8765/hero/animation.html to check it plays (click to replay).
  2. Capture 855 frames (28.5 s at 30 fps) at 1920x1080 with Playwright. Claude runs this through the Playwright MCP's browser_run_code_unsafe, in two calls of about 430 frames (about 40 seconds each); frames go to the gitignored .playwright-mcp/frames/: 
    await page.setViewportSize({ width: 1920, height: 1080 });
await page.goto('http://localhost:8765/hero/animation.html?capture');
await page.evaluate(() => document.fonts.ready);
for (let f = 0; f < 855; f++) {
  await page.evaluate((ms) => window.seek(ms), (f * 1000) / 30);
  await page.screenshot({ path: `.playwright-mcp/frames/f${String(f).padStart(4, '0')}.jpg`, type: 'jpeg', quality: 93 });
}
  3. Encode with an ffmpeg that has H.264 (Playwright's own ffmpeg only writes WebM). pip install imageio-ffmpeg in a throwaway venv gives one. Convert to standard color range, or PowerPoint shows it washed out: 
    ffmpeg -framerate 30 -i .playwright-mcp/frames/f%04d.jpg -vf "scale=in_range=full:out_range=tv,format=yuv420p" -color_range tv -c:v libx264 -preset slow -crf 18 -movflags +faststart docs/assets/hero.mp4
ffmpeg -ss 28.1 -i docs/assets/hero.mp4 -frames:v 1 -q:v 3 docs/hero/poster.jpg
  4. Screenshots: hero/agent-chat.jpg is the Command Center's chat panel answering "What's still blocking Miguel Reyes?" (cropped to the panel), and hero/dashboard.jpg is the dashboard with the Power Apps bar cropped off. Take them in Chrome at about 1372x820, then crop: -vf "crop=607:752:765:48" for the panel and -vf "crop=1372:752:0:48" for the dashboard.
  5. Delete .playwright-mcp/frames/ afterwards.

Build the demo video

The full demo video is built by scripts/build_demo_video.py from O'G's beat recordings. The edit is at the top of the script: for each beat, which stretches of the recording to keep, how fast to play them (anything faster than 1x gets a speed badge), the whole window (the script can crop, but O'G wants no zooms: viewers need the context), and the captions, timed in the recording's own seconds. A part can also pause on its last frame for a tour (tour=, as in beat 3's STUDIO_TOUR): the rest of the screen dims, a box moves to each part of the screen in turn, and a note beside it says what it is. Its boxes are in the recording's (or the slide's) pixels, each note goes on the first side where it fits unless the step names one, and the tour's caption is its own. A slide can have a tour too (tour= on the slide, as on the architecture). Scrolling through a response uses scroll(): only the stretches where the picture moves, so the stops between scroll-wheel turns are cut (measure them with a frame-difference pass over the recording). It draws the frame, captions and chapter cards with Pillow and joins everything with ffmpeg.

  1. The recordings go in videos-do-not-put-in-repo/, named as in the script (beat-1-m365-copilot.mp4 to beat-5-agent-in-code-app.mp4, plus creating-mgd-runtime-barrier-tracker.mp4 and beat-3-new.mp4 and pro-code-new.mp4, the second takes of chapters 2 and 4). A recording at another size gets its own 16:9 crop, like FULL_1908. The folder is gitignored and O'G keeps a copy on each laptop: never commit the recordings.
  2. Two deck slides appear in the video as stills, in git as docs/demo-video/<slide name>.png: prompt and architecture. The use-case and cast cards are drawn by the script (text in INTRO and CAST). If one of those slides changes, capture it again: serve docs/, open deck.html#<slide name> at 1920x1080 and screenshot that slide's .frame element (1647x926). Claude does this with the Playwright MCP. The logos on the tags at the window's top right are docs/demo-video/copilot-logo.png (beat 1, Microsoft 365 Copilot) and copilot-studio-logo.png (beat 2, Copilot Studio, from Microsoft's Power Platform icons); a beat gets a tag with brand=.
  3. In a throwaway venv, pip install pillow numpy imageio-ffmpeg (on an ARM64 laptop such as og-surface, make the venv with the x64 Python: py -V:3.13 -m venv <dir>, KI-35), then from the repo root run python scripts/build_demo_video.py. A full build takes about 25 minutes (the cards are drawn frame by frame; --only rebuilds take a few) and writes docs/assets/demo-video.mp4 and demo-video.vtt; work files go to videos-do-not-put-in-repo/build/work/. Commit the new MP4 and VTT. Each re-render adds about 80 MB to the repo's history (the file is 81 MB since 2026-11-03; GitHub refuses files over 100 MB, so a longer cut needs the final join's CRF raised from 18 to about 21, or Git LFS), so commit finished cuts, not every try. The poster is the title card at 2.5 s; refresh it if the opening changes: ffmpeg -ss 2.5 -i docs/assets/demo-video.mp4 -frames:v 1 -q:v 3 docs/demo-video/poster.jpg.
  4. The narration (O'G, 2026-11-03, ADR-0018) is in the script next to the captions: say= on a segment, a recording or a slide, say= on each tour step, and CHAPTER_SAY for the chapter cards (each runs on into its "What you'll see" card). Times are on the captions' clock; None means right after the line before, which is what to use for a line over a held last frame. The voice is VOICE, Grant on MAI-Voice-2.1 (public preview) in Azure Speech, from the Foundry resource named in .env (FOUNDRY_ACCOUNT), so the build needs az signed in to the demo tenant with Cognitive Services User on that resource (KI-36). Each line is generated once and kept in build/work/voice/, so changing a line sends only that line to the service. SAY_AS tells the voice how to say a few words (Microsoft 365, gpt-5.5, MAI-Voice-2.1, PT, MCP, 6 East). Before anything is drawn, the build makes room for every line: a tour step, card or slide stays up until its line ends, a sped-up stretch between two lines plays slower, or a frame holds a little longer. It mixes the lines into one track, and the captions file (demo-video.vtt) is the narration, word for word. Keep the lines inside the narration guardrails, like the captions.
  5. The deck follows the video slide for slide (O'G, 2026-11-03). Every build checks docs/deck.html against the video's order and stops with the list of slides it expects if they differ; then it writes the card slides (from CHAPTERS, BRIEFS and NEXT) each slide's place in the video (data-start, data-end, which the recording slides play, muted) and, at the end of each slide's notes, the narration spoken over it. python scripts/build_demo_video.py --deck does just that, from the last build. When a change adds, moves or removes a segment, change the deck's slides to match (each slide's data-seg names its segment; b6.1 is the second item of b6), and update the slide notes whenever captions change. Commit the deck with the video.
  6. Check it: python scripts/build_demo_video.py --review saves a frame from the middle of every caption, six to a sheet, in build/work/review/.
  7. After changing one beat, python scripts/build_demo_video.py --only b2 rebuilds just that segment and rejoins the rest (and any other segment whose length the narration changed). The keys are open (the title card), intro (the use case), hero, next (the "Now let's see it work." card, text in NEXT), cast, card1 to card7, brief1 to brief7 (the "What you'll see" cards, text in BRIEFS), b1 to b7 and end; after a new hero video, rebuild open, hero and end, and check the cut points (the title card, at the start and the end, starts where Deploy & govern has gone, 25.6 s, and the overview ends where it starts to leave, 25.0 s).

Foundry connection

The agent's Foundry tool runs on the connection amc-foundry-key with maker auth (ADR-0007). If the drafts start failing for everyone, check that connection first in Power Apps > Connections (og-svc).

To recreate it, run python scripts/create_foundry_connection.py. It reads the APIM key at runtime without printing or saving it, creates the connection if there isn't one with that name, and binds the agent's connection reference. Then retest with python scripts/test_foundry.py --apim and one draft prompt.

Azure provisioning

Both scripts are idempotent and read the subscription, resource group, region and names from .env (today: cuh-discharge-foundry2, cuh-discharge-apim2). Run them from Git Bash; they export MSYS_NO_PATHCONV=1 (KI-14).

bash infra/provision-foundry.sh   # RG, Foundry account, project, both deployments, your direct-call role
bash infra/provision-apim.sh      # APIM, managed identity + Cognitive Services User on Foundry,
                                  # then calls infra/apim_config.py: API /foundry policy, subscription discharge-navigator

apim_config.py exists because az rest crashes on Windows when it prints the APIM policy's BOM (KI-13); use it rather than az rest for policy changes. Details: Foundry.

Public snapshot

This repo stays private. A public copy is a scrubbed snapshot of its committed HEAD (ADR-0019).

  1. Commit what should be in the copy; uncommitted changes aren't included.
  2. python scripts/make_public_snapshot.py (or --out <folder>, outside this repo). The first run makes ../amc-agent-demo-public as a new git repo with one commit; later runs add a commit on top. It never pushes.
  3. If it stops with an edit that didn't match, the source text moved: update that entry in the script and run it again. If it stops on blocklisted text, add a swap or an edit for it. Nothing is committed in either case.
  4. Look at the files it lists as not text-checked (images and videos) before publishing.
  5. To publish, after Microsoft's open-source approval: create the public repo and push the copy from ../amc-agent-demo-public.

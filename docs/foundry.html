Foundry

Two model deployments in Foundry, one per drafting job (ADR-0005). The agent reaches them through APIM (ADR-0003) and the Foundry Deployments custom connector (ADR-0004). There's no Foundry agent here; each skill sends a chat completion to a deployment.

Deployments

Resource cuh-discharge-foundry2 (kind AIServices, SKU S0, custom domain cuh-discharge-foundry2), project amc-discharge-navigator, resource group rg-amc-agent-demo, East US 2. Created by infra/provision-foundry.sh, which is idempotent.

  • The tenant enforces disableLocalAuth=true, so there are no API keys (KI-01). Callers use Entra ID. admin@<tenant> has Cognitive Services User on the resource for keyless testing.

  • Preview and GA status was checked on 2026-10-19 (user guide). Re-check if you record much later.

Connector

The Power Platform custom connector Foundry Deployments is in connector/ (apiDefinition.swagger.json, apiProperties.json) and in the AMCDischargeNavigator solution. pac connector create gave it the default new_ schema prefix; that's cosmetic and not visible in the demo.

Connection referenceamc_DischargeNavigator.cr.shared_new-5ffoundry-20deployments-5fe712c9f154572394.5dff, with customconnectorid set (KI-15)

Why a connector instead of Copilot Studio's native Foundry model option: the built-in way to add a Foundry model to a prompt doesn't support GPT-5-family models (per Microsoft Learn, Oct 2026). The GitHub Copilot harness doesn't change that: its tools are connectors, MCP servers and workflows, and its model list doesn't include our deployments (KI-02, ADR-0004).

Add or change a deployment

  1. Add a deploy line to infra/provision-foundry.sh (deployment name, model, version, format, capacity) and run it. It skips what already exists.
  2. Smoke-test it. The script calls both deployments; add the new name to its loop if you need it tested too. 
    python scripts/test_foundry.py          # direct to Foundry, Entra token from az
python scripts/test_foundry.py --apim   # through APIM, the connector's path
  3. Point a skill at it: change the Model deployment value in agent/behaviors/<skill>/SKILL.md, and the deployment list in the Foundry tool's description, then push and publish (runbook). Log it in the edit log.
  4. Check preview or GA status before you call it either on camera.

If the connection ever needs recreating, copy the APIM key without printing it and create a new Foundry Deployments connection: runbook.

Check that a draft came from Foundry

From the agent's side, look for the Model: line. From the backend, use the Foundry resource's ModelRequests metric split by ModelDeploymentName. Always pass explicit --start-time and --end-time. Without them, the time buckets are misleading, and on 2026-10-19 they made it look as if no calls had been made (KI-12).

MSYS_NO_PATHCONV=1 az monitor metrics list \
  --resource /subscriptions/<subscription-id>/resourceGroups/rg-amc-agent-demo/providers/Microsoft.CognitiveServices/accounts/cuh-discharge-foundry2 \
  --metric ModelRequests --aggregation Total --interval PT15M \
  --filter "ModelDeploymentName eq '*'" \
  --start-time 2026-10-19T12:00:00Z --end-time 2026-10-19T14:00:00Z -o table

Replace the times with the window you tested in (UTC). On 2026-10-19 this showed patient-summary and prior-auth each called once per test round (results log).

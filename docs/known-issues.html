KI-01 Workaround No Foundry API keys. disableLocalAuth=true is set on the Foundry resource (enforced by the old tenant; also set on cuh-discharge-foundry2), so it only accepts Entra ID tokens. APIM cuh-discharge-apim2 calls Foundry with its system-assigned managed identity, which has Cognitive Services User on the Foundry resource (ADR-0003). For keyless testing, admin@<tenant> also has Cognitive Services User: python scripts/test_foundry.py (direct) and --apim (through APIM).
KI-02 Workaround Copilot Studio's native "bring your own Foundry model" prompts don't support GPT-5-family models (per Microsoft Learn, Oct 2026). The GitHub Copilot harness doesn't help: its model list doesn't include our Foundry deployments, and its tools are only connectors, MCP servers and workflows. The custom connector Foundry Deployments calls APIM with Ocp-Apim-Subscription-Key, and each skill passes the deployment name (ADR-0004). If someone asks "why not the native prompt?" on camera, this is the answer.
KI-03 Workaround pac copilot init always creates its own solution and publisher. The solution is named after the schema and the publisher after the prefix, and you can't choose otherwise. On 2026-10-19 it created solution amc_DischargeNavigator (bot only) and a second publisher amc. Claude didn't report them; O'G found and deleted both. If you ever init again, report both side effects in the same turn and remove them right away. Then check that the bot, its components, the tables and the connection references are still in AMCDischargeNavigator (runbook).

KI-09 Info Mistral-Large-3 answered "GPT" when asked to name itself in testing. Models don't reliably know their own name. Never ask a model what it is on camera. Point at the Model: line each skill adds from the response's model field, and at the deployments list in Foundry (ADR-0005).
KI-10 Info Microsoft 365 Copilot's Graph indexing has no published time. It's usually hours. The beat 1 recall may find the seeded emails but not the earlier Discharge Navigator chat. Seed early (done 2026-10-19), then run the beat 1 prompt a few hours later or the next day. Don't promise on camera that it finds the agent chat (ADR-0011, runbook).
KI-11 Info Conversation transcripts reach Dataverse only after the session goes idle. Right after a test, there's nothing to read. To verify from the backend that the drafts came from Foundry, use the Foundry ModelRequests metric (KI-12) and the saved draft columns on the plan, not transcripts (Foundry).
KI-12 Info Foundry ModelRequests metric buckets are misleading without an explicit time window. A first query on 2026-10-19 wrongly suggested no calls had been made. Filter by ModelDeploymentName and always pass explicit --start-time and --end-time (Foundry).
KI-13 Workaround az rest crashes on Windows when it prints APIM's policy XML, which starts with a BOM. infra/provision-apim.sh calls infra/apim_config.py, which applies the policy and creates the subscription with an ARM token instead of az rest (runbook).
KI-14 Workaround Git Bash rewrites /subscriptions/... arguments into Windows paths, which breaks az ... --scope and ARM URLs. Set MSYS_NO_PATHCONV=1 (the infra scripts export it), or use PowerShell.
KI-15 Workaround A connection reference for a custom connector needs customconnectorid set, or solution export fails. The Foundry Deployments connection reference is linked to the connector record (done 2026-10-19). If you recreate it, set the link before exporting (runbook).

KI-27 Workaround Apps in Copilot Studio don't build in the environment Copilot Studio is pointed at. They run on Copilot Managed Runtime, which always builds in the maker's own personal developer environment. Routing for it is on in every tenant and can't be turned off. Here the router put admin@<previous-tenant> in og-dv ("Default Environment Group"), which doesn't have our tables. Asked to use Discharge Tasks, the builder replied asking for an environment ID and table names. Given the address, ID and logical names, it then refused og-ai-dev outright: "App Builder doesn't recognise that environment's database address as one it supports". Reading through the existing Dataverse connection was refused too. It created an empty, unpublished "Barrier Tracker" in its own environment. Microsoft's docs don't say whether these apps can reach Dataverse in another environment. Seen 2026-11-01 (Learn: environment routing for Copilot Managed Runtime). Worked around by moving tenants (ADR-0015). In the demo tenant the builder reads Dataverse in the personal environment (og-dev) and across environments (og-svc). Background, from the old tenant: Naming og-ai-dev by its web address (the deck's request slide) wasn't enough. A test against the standard Account table in the builder's own environment (og-dv) was refused the same way, so the builder won't connect to Dataverse anywhere in this tenant. All the environments involved are ordinary US-region, managed Developer environments on Dataverse 9.2, and Dataverse is on the app builder's default connector allow list. Nothing in the tenant explains it, so it needs the Copilot Studio product team or Microsoft support. Don't fix it by copying the tables into og-dv: that splits the data from the agent and the Command Center. And don't add og-ai-dev to the routing group: that group's default connector allow list would block our Foundry Deployments custom connector.
KI-28 Info Dataverse Python SDK 1.0.0 rejects create_schema.py's column specs ("Unsupported column spec type ... expected str or Enum subclass"). The script was written against an earlier SDK that took dicts with display names and lengths; 1.0.0 only takes a type name and makes up the display name. Seen 2026-11-01 on the second laptop. Fixed: create_schema.py now posts table and column metadata to the Web API directly, matching the original tables (date-only columns UserLocal, Name required with length 850). It also adds any missing columns to a table that already exists, and retries Dataverse's transient "unexpected error" (0x80040216).

KI-32 Workaround The Copilot Studio connector's documented "Execute Agent and wait" (ExecuteCopilotAsyncV2) rejects GitHub Copilot harness agents, so a Code App can't call Discharge Navigator with it. The connector's internal ExecuteCopilotAsyncV2OnAgenticRuntime works, but it's undocumented, and the generated schema types its 200 response as void, which drops the reply. Code App v1.2.0 calls the agentic-runtime operation with notificationUrl: "" and widens the 200 response to an object at load (code-app/src/data/agentClient.ts), the same pattern as the-agents repo. Microsoft can change or remove it; the supported fallback is a Copilot Studio workflow with an agent node (ADR-0017). The panel can't show a sign-in or consent card: if one comes back, it tells the user to allow the connection in Teams once.
KI-33 Workaround The npm pa CLI keeps its own sign-in, separate from pac. On 2026-11-01, pac was on admin@<tenant> (og-svc) while npx --no-install pa auth status still said admin@<previous-tenant>. KI-34 Fixed Chrome 156's scrollIntoView() returns a value (it used to return undefined). A React effect written as a one-line arrow, useEffect(() => ref.current?.scrollIntoView(), …), hands that value to React as its cleanup. React calls it on the next render, throws "destroy is not a function", and unmounts the app. In Code App v1.2.0 the whole screen went white when the agent's reply arrived. Write effects with braces so they return nothing (v1.2.1, AgentPanel.tsx). To see a crash inside the Power Apps player, whose cross-origin frame hides the console: run npm run dev in code-app/, open the Local Play URL it prints (Chrome asks once to allow local network access), and pass onUncaughtError to createRoot to print the error on the page.
KI-35 Workaround imageio-ffmpeg has no ffmpeg for ARM64 Windows. On og-surface (ARM64), a venv made with the default ARM64 Python installs imageio-ffmpeg, but get_ffmpeg_exe() fails with "No ffmpeg exe could be found", so build_demo_video.py and the hero video's H.264 step can't run. Make the throwaway venv with the x64 Python, which is installed on og-surface too: py -V:3.13 -m venv <dir>. Its wheel bundles the x64 ffmpeg, which runs under emulation; the full demo video build still finishes in a few minutes (Runbook).
KI-36 Workaround Azure Speech with Entra ID wants its own token format. The Foundry resource has no keys (disableLocalAuth), so the demo video's narration signs in with Entra ID, and Speech's REST API takes the Entra token wrapped with the resource ID, not on its own (Microsoft's text to speech REST docs). Send Authorization: Bearer aad#<resource id>#<Entra token for https://cognitiveservices.azure.com> to https://<resource>.cognitiveservices.azure.com/tts/cognitiveservices/v1 (the voice list is at /tts/cognitiveservices/voices/list). The az account needs Cognitive Services User on the resource; admin@<tenant> has it. build_demo_video.py does this (speech_auth()).

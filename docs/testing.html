Check scripts

Run from the repo root. They use the signed-in az account (AUTH_MODE=azcli in .env), so az must be on the M365x tenant (KI-08).

ScriptWhat it checks
scripts/preflight.pyLists publishers and whether the solution and the three amc_ tables exist. Written as a collision check before create_schema.py; also a quick "is everything there" check.
scripts/verify_seed.pyPlans by status, unit and readmission risk; O'G's active caseload; plans missing the patient lookup; and Miguel Reyes's tasks with their status and barrier flag.
scripts/expected_kpis.pyComputes the Code App's KPI values from Dataverse with the same rules as code-app/src/data/metrics.ts: expected discharges today, medically ready but still here (and avoidable bed-days), open barriers, median prior-auth hours, high risk, and the top of the table.
scripts/test_foundry.pyCalls both deployments (patient-summary, prior-auth) on the OpenAI v1 chat completions endpoint and prints [PASS] <deployment> -> model=…. Default: direct to Foundry with an Entra token (the tenant disables keys). --apim: through APIM with the subscription key, the path the connector uses. The key is fetched at runtime and never printed.
python scripts/preflight.py
python scripts/verify_seed.py
python scripts/expected_kpis.py
python scripts/test_foundry.py
python scripts/test_foundry.py --apim
cd code-app && npm run build

Testing each layer on its own

LayerHow
Foundry deploymentspython scripts/test_foundry.py (Entra token, direct).
APIM → Foundrypython scripts/test_foundry.py --apim (subscription key, APIM's managed identity to Foundry). Details: Foundry: APIM.
Connector connection amc-foundry-keyThe Chat completion action through the Power Platform connector runtime (Power Platform → APIM → Foundry). Details: Foundry: connector.
Dataverse MCP serverWatch the tool calls in the Copilot Studio Test pane. read_query is SQL; choice, boolean and lookup labels come back in <column>name columns (KI-18).
Agent, draft versionCopilot Studio Test pane. Shows the activity, including each Chat completion call and its Model deployment input.
Agent, published versionTeams or Microsoft 365 Copilot. Runs as the signed-in user for Dataverse (end-user auth, ADR-0007). Publish first after a change (runbook).
Did the drafts really come from Foundry?The Model: line in the reply, and the Foundry ModelRequests metric split by ModelDeploymentName. Always pass explicit --start-time and --end-time; without them the buckets are misleading (KI-12, Foundry: metrics).
Saved draftsThe Command Center drawer (Agent drafts, then Reload), or the plan's amc_patientsummary and amc_priorauthpacket columns.
Conversation transcriptsThey reach Dataverse only after the session goes idle, so don't expect them right after a test (KI-11).
Code AppThe deployed app (user guide), Refresh, and compare with expected_kpis.py. npm run build must be clean before any deploy.

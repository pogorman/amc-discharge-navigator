AMC Discharge Navigator, explained simply

What the demo shows, without the product names getting in the way. For how it's built, see the technical guide.

The one-sentence version

A patient is well enough to go home but is still in a hospital bed. An assistant tells the case manager why, writes the two documents that will get him out, and the whole care team sees the same up-to-date plan, whether they're in Teams, a simple app or a leadership dashboard.

The cast

What happens when you ask something

  1. The case manager asks the assistant in Teams: "What's holding up Miguel Reyes's discharge?" → The assistant reads Miguel's plan from the record, using the case manager's own permissions. → It answers with three open barriers: the insurer's approval for a skilled nursing facility (SNF), the SNF accepting him, and the wheelchair van. Each comes with who owns it and the latest notes.
  2. The case manager asks: "Build the SNF prior-auth packet for Miguel Reyes." → The assistant collects the facts from the chart: the hospital stay, the tasks and the insurer's request. → It sends them through the gatekeeper to the packet writer (gpt-5.5). → The packet comes back marked DRAFT, with the model's name on the last line. It quotes the walking distance the insurer asked for ("150 ft with a rolling walker and standby assist"), which was already in the chart. → If the case manager says so, the draft is saved to the plan, and it appears in the dashboard for review.
  3. In the morning huddle, the nurse manager marks the SNF acceptance done in the huddle board. → It's the same row in the same record, so the next time anyone asks the assistant, that barrier is gone. The dashboard shows one fewer open barrier.

Why two writers

They do different jobs, so each gets the model that suits it:

JobWriterWhat good looks like
Patient instructionspatient-summary (Mistral Large 3, preview in Foundry)Short sentences at a 6th-grade reading level, in the patient's language (Spanish for Miguel), with teach-back questions
Prior-auth packetprior-auth (gpt-5.5)Structured sections, a chart citation for every statement, nothing invented, and a list of what the insurer still needs

A third model, Claude Sonnet 4.6, runs the assistant itself: it decides what to look up and which writer to call. You can always see which writer produced a draft, from the Model: line at the end. Nobody has to ask the model who it is.

Why this matters

  • One plan, three kinds of builder, one platform. A nurse manager with no code, an agent builder in Copilot Studio, and a pro developer in VS Code all work on the same governed data.
  • People stay in charge. Every model output is a draft. A nurse reviews and signs the patient instructions; the case manager reviews the packet before anything goes to the insurer.
  • Time back where it hurts. The facts are already in the chart. The assistant finds them and drafts the paperwork, so the team spends its time on the patient instead of on hunting and retyping.

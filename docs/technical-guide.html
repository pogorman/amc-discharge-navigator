Request flow

The numbered flows

#FlowWhat happens
1AskA case manager chats with Discharge Navigator in Teams or Microsoft 365 Copilot. Claude Sonnet 4.6 reads the instructions and decides which skill and tools to use.
2Read and save in DataverseThe Dataverse MCP server runs as the signed-in user, so Dataverse security still applies. It can query, search and describe, plus update_record to save a draft. It can't create, delete or change tables (ADR-0007).
3Hand the writing to a model in FoundryA skill calls the Foundry Deployments connector (Chat completion) with the deployment name, the system prompt and the facts. It reaches APIM with a subscription key held in the maker connection, so users never see it.
4APIM to FoundryAPIM drops the subscription key header, authenticates with its own managed identity and calls /openai/v1/chat/completions. The draft and its model field come back the same way, and the agent adds the Model: line.
5Code AppThe Discharge Command Center reads plans, patients, tasks and saved drafts, and writes "Mark complete" on tasks. Reload in the drawer picks up a draft saved from Teams.
6Barrier TrackerA nurse manager describes it in plain language, and Apps in Copilot Studio (preview) builds it in og-svc (KI-31). It reads and edits the same tasks through a connection made as her (ADR-0014). In beat 4 it closes a barrier that the agent and the Command Center then both drop (ADR-0012), and beat 6 plays a recording of the build (ADR-0016).
7Graph recallMicrosoft 365 Copilot finds the Maple Grove and payer emails (seeded 2026-11-01 in this tenant) for beat 1. It may not find the agent chat itself (ADR-0011).

  1. You type it in Microsoft 365 Copilot or Teams (flow 1).
  2. Sonnet 4.6 matches it to the prior-auth-packet skill.
  3. The skill reads DP-1001 Miguel Reyes, his patient record and every task, including the notes, through read_query as you (flow 2).
  4. The skill calls Chat completion with deployment prior-auth, the prior-auth system prompt and the labelled facts (flow 3). APIM authenticates to Foundry, and gpt-5.5 writes the packet (flow 4).
  5. The agent returns the text unchanged and adds Model: gpt-5.5-… | Draft for case manager review.
  6. You say save, and the agent writes it to amc_priorauthpacket on the plan with update_record (flow 2).
  7. In the Command Center, open Miguel's drawer and select Reload. The packet appears under Agent drafts (flow 5).

Patient instructions follow the same path with the patient-discharge-summary skill and deployment patient-summary (Mistral-Large-3, Preview). The draft comes back in Spanish because that's Miguel's preferred language in the chart. When saved, it goes to amc_patientsummary with Summary Status Draft.

Components

Discharge Navigator (Copilot Studio)

  • GitHub Copilot harness agent with no topics, created from the CLI with pac copilot init. A harness can't be changed after creation.
  • Orchestrating model: Claude Sonnet 4.6, pinned explicitly. It orchestrates; the Foundry deployments write the drafts.
  • Tools: the Dataverse MCP server (end-user auth, trimmed to read_query, search, describe, search_data, update_record) and Foundry Deployments Chat completion (maker auth).
  • Skills: patient-discharge-summary and prior-auth-packet. Each returns the model's text unchanged and offers to save it to the plan.
  • "My patients" is fixed to Patrick O'Gorman in the instructions (ADR-0008, KI-20).

Instructions, skill prompts, test prompts and the edit log: Copilot Studio.

Foundry, APIM and the connector

  • The tenant enforces disableLocalAuth=true on Cognitive Services, so Foundry has no keys (KI-01). APIM's system-assigned identity has Cognitive Services User on Foundry.
  • The connector's one action, Chat completion, takes a Model deployment input (the deployment name) and the messages. It authenticates to APIM with Ocp-Apim-Subscription-Key.
  • Copilot Studio's native "bring your own Foundry model" prompts don't support GPT-5-family models, which is why we use the connector (KI-02).

Deployments, APIM policy and metrics: Foundry.

Dataverse

Three tables: amc_patient (stands in for the EHR), amc_dischargeplan (lookup amc_PatientId) and amc_dischargetask (lookup amc_DischargePlanId). A barrier is a task with amc_isbarrier = true whose status isn't Completed. The LACE score is computed in the seed script. Columns, choices and seed data: Dataverse.

Barrier Tracker (Apps in Copilot Studio, preview)

Built once from the prompt on the deck's request slide: Copilot Studio > Home > App (preview). It runs on Copilot Managed Runtime, was built in og-svc next to the data, and reads and writes the tables through the Dataverse connector's selected-environment operations, with a connection made as her (ADR-0014, KI-31). Beat 4 uses the published app live, and beat 6 plays O'G's recording of the build (ADR-0016). It isn't kept in the repo.

Discharge Command Center (Code App)

House-wide KPIs, barrier and bed-day panels, the plans table, a plan drawer with the agent's drafts, and a chat with the agent (ADR-0017). Details in Code App below.

  • Stack: React 19, Vite 7, TypeScript, Fluent UI v9, the Power Apps SDK (@microsoft/power-apps) and react-markdown 10.1.0. The pa CLI (@microsoft/power-apps-cli) is a local devDependency, so run npx --no-install pa … from code-app/ (KI-22).
  • Data: three Dataverse data sources through the generated services. useDischargeData loads all plans, tasks and patients and joins them in memory. Only real columns are selected; the generated *name fields are virtual.
  • The one write: completeTask sets Task Status to Completed and Completed On to now, then reloads so every view agrees. The drawer's Mark complete button calls it.
  • Drafts: DraftViewer renders amc_patientsummary (with its Not Started / Draft / Signed badge) and amc_priorauthpacket as Markdown. Raw HTML isn't rendered.
  • Dates: date-only columns come back as YYYY-MM-DDT00:00:00Z, so the app compares on the date part (KI-17).
  • KPI rules: listed on the Dataverse page. scripts/expected_kpis.py computes the same numbers from Dataverse.
  • Deploy: bump the version, npm run build, pa app push. Ask O'G first. Steps and the --solution-id workaround: Runbook.

Barrier Tracker → DataverseThe signed-in user, through Power AppsSame tables, same security.
CLIs (pac, pa, az)admin@<tenant>The sign-ins are machine-wide, so if another terminal switches tenants, scripts break (KI-08).
  • Governance: og-svc is a Managed Environment. Everything we built is in the AMC Discharge Navigator solution. There's no DLP policy in the tenant yet. One is optional for the governance beat; it's a tenant-level change, so it waits on O'G.
  • Model choice is visible in three places: the deployment name in each skill (patient-summary, prior-auth) and in the tool call shown in the agent's activity; the model field returned with each reply (the Model: line); and the deployments list in the Foundry portal. Never ask a model to name itself on camera.
  • Drafts, not decisions: both skills end every output with a draft marker. A clinician reviews and signs.
  • Secrets: nothing in the repo is a secret. .env is gitignored and holds IDs only. The APIM key lives in the maker connection; copy it to the clipboard without printing it (Runbook).

Extending

To…Do this
Change the agent's instructions, tools or skillsEdit agent/, then pac copilot pull before pac copilot push, then publish. Check the preferred solution before and solution membership after (KI-05). Log it in the edit log. Steps: Runbook.
Add a skillWrite it flat as agent/behaviors/<name>.mcs.yml (kind: InlineAgentSkill) and push. PAC rewrites it to behaviors/<name>/SKILL.md + skill.mcs.yml.
Use another modelAdd a deployment in Foundry (infra/provision-foundry.sh), then name it in a skill. The connector takes the deployment name as an input, so the connector and APIM don't change. Record it in Decisions.
Add a table or columnscripts/create_schema.py only creates tables that don't exist yet; add columns to existing tables with the Dataverse metadata tools. Then re-export the solution (Runbook), and refresh the Code App's data source with the code-apps plugin. Never hand-edit code-app/src/generated/.
Change the Code AppEdit code-app/src, bump src/version.ts and package.json, build, then deploy once O'G says so (Runbook). Add a changelog entry.
Change the architectureAdd an ADR to Decisions and update the diagram on this page.

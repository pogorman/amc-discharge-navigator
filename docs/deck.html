The nurse manager's request

Typed into Copilot Studio: Home > App (preview), exactly as written

NM

6 East nurse manager

I'm the nurse manager on 6 East. Every morning at huddle we go through what's keeping patients from going home, and I want a simple board for it. Call it Barrier Tracker.

Build it in our og-svc environment (environment ID <environment-id>) and use the Discharge Tasks and Discharge Plans tables we already have there, not made-up data. Read and update them with the Dataverse connector's selected-environment operations, passing og-svc's address (og-svc.crm.dynamics.com), through my existing Dataverse connection in og-svc. Don't add them as table data sources or connect to the database directly.

Show the open discharge barriers for 6 East: tasks marked as a discharge barrier that aren't completed. For each one, show the patient, the barrier, who it's assigned to, its status, the due date and the latest notes. Put the ones due soonest at the top.

Let me open a barrier, add a note and mark it completed, with today's date as the completed date. Nobody should be able to delete anything.

Make it easy to read on the big screen in the huddle room.

The reveal. The video's caption: "The reveal: she built Barrier Tracker herself, from this one request." Then:

"This is all she typed. What the huddle needs to see, the tables the hospital already has, what she wants to change, and that nobody can delete anything. Plain language."

Why the second paragraph is technical. The app builder's table data sources only accept Dataverse's usual address pattern (org…crm.dynamics.com), and og-svc has a custom address (og-svc.crm.dynamics.com). The connector's current-environment operations fail there too ("invalid organization URL"), so the prompt asks for its selected-environment operations with og-svc's address, through her existing connection. That still runs through the connector and her connection, not a direct database connection. It also gives the environment ID, so the builder doesn't stop to ask for it or start an admin connection to look it up (KI-31). Tested 2026-11-01: the builder built the app in og-svc and showed real data, in the preview and after publishing.

To rebuild the app (off camera; the huddle uses the one you already built): Copy prompt, then paste it into Copilot Studio > Home > App (preview). Approve the actions it asks for ("Approved 1 action"). If it asks which operations to use, pick the selected-environment ones with og-svc's address. Delete the previous Barrier Tracker first, and any "Power Platform for Admins" connection the builder started in og-svc.

If anyone asks how it's governed:

  • As her: every person who opens the app connects to Dataverse with their own account. Two people can open the same app and see different rows.
  • Governed: apps built in Copilot Studio run on Copilot Managed Runtime. They sign in with Entra ID and follow the environment's policies from the moment they're created.

  • IT can see it: every app shows up in the Microsoft 365 admin center inventory, with its owner.
